## 1. 무엇을 하는 도구인가

**TODO Flow는 사람이 고른 개발 작업을 에이전트 실행·검증·독립 리뷰로 연결하고, 중단 후에도 같은 기록에서 이어갈 수 있게 하는 도구다.** 작업을 등록하는 것과 실행을 승인하는 것은 다르다. 문서를 먼저 읽고 범위를 정한 다음, 실제 트랙 ID를 지정해 실행한다.

55번 폴더는 도구의 소스 저장소다. 이 도구로 수정할 업무 프로젝트는 별도로 지정한다. 예컨대 다른 프로젝트에 기능을 추가하려면 그 프로젝트를 대상으로 초기화해야 한다. 55번에 도구를 설치했다고 다른 프로젝트가 자동으로 연결되지는 않는다.

```text
사람: 요구 작성 → 작업 문서 검토 → 실행할 ID 선택 → 실행 승인
                    ↓                              ↓
                 등록된 트랙                  trackrun 실행
                                                   ↓
                                  워커의 변경 제안 → 엔진 적용·검증
                                                   ↓
                                             독립 리뷰
                                      ┌────────────┴────────────┐
                               review 종료점              land 허용 시
                               검토된 후보 보존       병합 → 후속 점검 → 완료

중단·질문 발생 → 같은 상태 기록 확인 → 답변·재개 → 결과와 외부 반영 확인
조건부 관찰 → watchlist 재평가 → 필요한 후속 TODO 등록 → 사람의 새 선택
```

이 도식은 이해를 돕는 대표 경로다. 모든 작업이 고정된 감독·코디네이터 세션을 차례로 거치는 구조는 아니다. 워커가 현재 필요한 제한된 작업을 제안하고, 엔진이 작업권·검증·변경 적용을 관리한다.

### 처음 알아둘 용어

| 용어 | 실제 의미 |
|---|---|
| 트랙(track) | 목표·범위·성공 조건·근거를 가진 하나의 개발 요구다. 사람이 읽는 문서와 고유 ID가 있다. |
| 상태(state) | 프로젝트의 설정·작업·결과·질문·외부 반영 기록을 보존하는 폴더다. 기본 이름은 `todo/`다. |
| 워커(worker) | 필요한 파일을 읽고 변경안을 제안하는 에이전트 실행이다. 엔진 자체와 다르다. |
| 드라이버(driver) | 요청된 작업을 배정하고 워커를 진행시키는 실행 프로세스다. |
| 워크트리(worktree) | 트랙별 변경을 분리하는 Git 작업 폴더다. |
| 리뷰(review) | 구현과 별도 에이전트 문맥에서 정확한 후보·검증 결과를 검사하는 단계다. |
| 랜딩(land) | 검증한 변경을 기준 브랜치에 반영하는 과정이다. 별도 허용이 필요하다. |
| 관찰(watch) | 당장 실행하지 않는 조건부 사항이다. 유보 이유·재개 조건·다음 행동이 있어야 한다. |

## 2. 현재 설치 상태와 실행 전 경계

**아래 설치 표는 2026-09-24 관측이다. 현재 설치·실행·GitHub 상태는 재확인하지 않았으며, 이후 로컬 수동 Orca 연결 계약은 루트 운영가이드의 별도 refer를 따른다.**

| 항목 | 현재 값 |
|---|---|
| 도구 소스 | `<WORKSPACE_ROOT>/55.todo-flow` (이 저장소의 로컬 clone 위치) |
| CLI | `~/.local/bin/todo-flow`, `~/.local/bin/trackrun` (`uv tool dir --bin` 기준) |
| 설치 환경 | `~/.local/share/uv/tools/todo-flow` (uv tools 기준) |
| 버전 표시 | `0.0.1` — 공개 릴리스 wheel이 아니라 위 SHA의 개발 소스 빌드다. |
| 포크 | `dyoon98-creator/todo-flow` |
| 원본 | `JakeB-5/todo-flow` |

현재 개발 소스는 워커에게 파일 경로를 주고 필요한 내용을 직접 읽게 한다. 공개 v0.0.1 wheel의 스냅샷 전달 방식과 다르므로, 버전 문자열 하나만으로 같은 동작이라고 판단하면 안 된다.

**주의: `review`는 읽기 전용 모드가 아니다.** 엔진이 파일을 적용하고 커밋하거나 원격 브랜치·PR을 게시할 수 있다. `land`를 허용하지 않았다는 사실은 병합 경계일 뿐, 모든 외부 변경을 금지한다는 뜻이 아니다.

또한 기본 워커는 raw Codex·Claude CLI를 호출한다. Orca 창에 보인다는 이유만으로 로컬의 서명된 위임·모델 정책과 연동된 것은 아니다. 실제 업무에 사용하기 전, 승인된 실행 어댑터와 대상 프로젝트의 커밋·게시 권한을 먼저 확정해야 한다. 이 가이드의 실행 예시는 그 조건을 충족한 뒤 사용하는 절차이며, 현재 세션에 대한 실행 승인이 아니다.

## 4. 새 업무 프로젝트를 준비하는 순서

### 준비물과 승인

대상 Git 저장소에 초기 커밋·작성자 정보·`origin`이 있어야 한다. Python 3.11 이상, uv, Git, 인증된 선택 CLI가 필요하며 GitHub 연동에는 인증된 `gh`가 추가로 필요하다. 인증값을 문서·설정·대화에 복사하지 않는다.

먼저 대상 프로젝트의 `AGENTS.md`, 기존 변경, 실제 기준 브랜치, 성공하는 검증 명령, 수정 가능한 파일 범위를 확인한다. 이미 초기화된 프로젝트는 기존 설정을 재사용한다. `todo/`를 다른 도구가 쓰고 있다면 별도 상태 경로를 택한다.

다음 요청문을 에이전트에게 주면 준비 범위를 분명히 할 수 있다.

```text
55.todo-flow의 운영가이드에 따라 [대상 프로젝트 절대경로] 연결을 준비해 주세요.
기존 변경과 상태 폴더를 보존하고, 기준 브랜치·검증 명령·쓰기 범위를 먼저 확인해 주세요.
기본 언어는 한국어입니다. 현재 실행 정책과 어댑터가 맞는지도 확인해 주세요.
이번 요청은 준비까지만입니다. trackrun, 커밋, push, PR 게시, 병합은 실행하지 마세요.
확인된 설정과 다음 승인 항목을 알려 주세요.
```

### 설정 예시

아래는 **Python 프로젝트를 설명하기 위한 예시**다. `/absolute/my-project`, 브랜치, 검증 명령, 패턴을 실제 승인값으로 바꾸기 전에는 실행하지 않는다. 셸을 새로 열면 변수를 다시 선언한다.

```sh
FLOW_PROJECT='/absolute/my-project'
FLOW_STATE="$FLOW_PROJECT/todo"
FLOW_SKILLS="$FLOW_PROJECT/.agents/skills"

git -C "$FLOW_PROJECT" status --short
git -C "$FLOW_PROJECT" rev-parse --verify HEAD

todo-flow --state "$FLOW_STATE" init \
  --repo "$FLOW_PROJECT" --base main --worker codex --language ko \
  --verify '["python3","-m","unittest","discover","-v"]' \
  --write 'src/*.py' --write 'tests/*.py' \
  --context 'src/*.py' --context 'tests/*.py' --context README.md

todo-flow --state "$FLOW_STATE" install-skills --target "$FLOW_SKILLS"
```

`--verify`는 셸 문자열이 아니라 JSON 인자 배열이다. `--write`는 허용 쓰기 범위이며, `--context`는 탐색 안내일 뿐 읽기 접근을 제한하는 보안 경계가 아니다. Claude 프로젝트는 `.claude/skills`를 사용한다. `--github OWNER/REPOSITORY`는 GitHub 연동이 승인되고 정확한 대상이 확인된 경우에만 추가한다.

성공 확인은 CLI 종료 코드만으로 끝내지 않는다. 생성된 상태 경로, `config/1.json`의 대상·언어·검증·종료점, 설치 스킬의 `project.json` 연결을 대조한다. 실행 중 설정을 직접 바꾸거나 `init`을 다시 실행하지 않는다.
