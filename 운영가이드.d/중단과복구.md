## 7. 멈춤·질문·재개

아래 명령은 상태를 바꿀 수 있다. 실제 상태 경로와 대상 ID를 확인하고, 이미 발생한 커밋·원격 게시를 되돌리는 명령으로 오해하지 않는다.

```sh
todo-flow --state "$FLOW_STATE" status
todo-flow --state "$FLOW_STATE" pause ACTUAL_TRACK_ID
todo-flow --state "$FLOW_STATE" resume ACTUAL_TRACK_ID
todo-flow --state "$FLOW_STATE" answer ACTUAL_DECISION_ID --text '실제 판단과 이유'
todo-flow --state "$FLOW_STATE" run
```

중단 후에는 **같은 상태 경로**에서 기록을 확인한다. `resume`이나 `answer` 뒤 드라이버가 없다면 `run`이 추가로 필요할 수 있다. 기술적 실패를 사용자 답변으로 꾸며 통과시키지 않는다. 취소하려면 `cancel ACTUAL_TRACK_ID`를 사용하되, 취소를 기존 변경·원격 효과의 자동 원복으로 간주하지 않는다.

대시보드 연결이 끊어져도 작업 완료가 아니다. 터미널이 닫혔어도 성공으로 판단하지 않는다. 소유권·시도·실제 종료·결과를 대조한 뒤 재개한다.

## 9. 보존·업데이트·문제 해결

**파일이 정본이고 SQLite는 재생성 가능한 조회 캐시다.** 상태 폴더 전체, 대상 Git 이력·작업 중 변경, 설치 스킬의 사용자 수정, 외부 효과 기록을 보존한다. 백업은 작업과 관련 프로세스가 멈춘 시점에 별도 날짜 폴더로 복사한다. 실행 중 파일 일부만 복사한 것을 일관된 백업으로 간주하지 않는다.

```sh
todo-flow --version
trackrun --version
todo-flow --state "$FLOW_STATE" compatibility --target "$FLOW_SKILLS"
todo-flow --state "$FLOW_STATE" update-skills --target "$FLOW_SKILLS" --dry-run
todo-flow upgrade --wheel /absolute/trusted/new-release.whl --dry-run
```

업데이트는 먼저 dry run 결과와 충돌을 읽는다. 엔진 교체 전에는 알려진 프로젝트의 실행기·대시보드를 모두 안전하게 멈춰야 한다. 실제 적용은 별도 승인 범위에서 수행하고, 반환된 백업 ID·복구 명령을 보존한다. 소스 빌드를 오래된 공개 wheel로 바꾸면 현재 기능이 사라질 수 있다. 현재는 최신 버전 자동 탐색이나 미래 형식 자동 마이그레이션을 전제로 운영하면 안 된다.

| 증상 | 먼저 확인할 것 | 피할 행동 |
|---|---|---|
| 명령을 못 찾음 | `uv tool dir --bin`과 PATH, 설치 링크 | 같은 이름의 다른 패키지를 임의 설치하지 않는다. |
| 작업이 움직이지 않음 | 요청 여부, 드라이버 존재, 질문·pause 상태, 배정 상한 | 등록을 실행 성공으로 보고하지 않는다. |
| 워커 창만 보임 | 실제 PID·exit·결과 파일 | 다른 실행기로 중복 기동하지 않는다. |
| 검증 실패 | 실패 로그, 기준 소스, 실제 검증 명령 | 검증 조건을 약화해 통과시키지 않는다. |
| 스킬 업데이트 충돌 | 관리 baseline과 사용자 수정 | 폴더 전체를 삭제·덮어쓰지 않는다. |
| 세션 중단 | 같은 상태의 시도·결과·외부 효과 기록 | 다시 `init`해 기록을 갈아엎지 않는다. |
