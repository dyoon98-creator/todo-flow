## 6. 검수와 완료 판단

워커가 변경안을 냈다는 사실, 터미널이 열렸다는 사실, 프로세스가 끝났다는 사실은 각각 다른 증거다. 다음 항목을 순서대로 확인한다.

1. 실제 대상 트랙·문서 리비전·후보 SHA가 맞는지 확인한다.
2. `attempts/`의 `launch.json`, `terminal-process.json`, `output.json`, `stderr.log`를 확인한다. 토큰 등 민감한 원문은 공유하지 않는다.
3. `results/`와 검증 결과에서 성공 조건별 판정·실패·누락을 확인한다.
4. 독립 리뷰가 같은 후보를 검사했는지 확인한다. 같은 GitHub 계정의 COMMENT 리뷰는 다른 사람의 APPROVE와 다르다.
5. 원격 효과가 있다면 `effects/`의 기록과 실제 이슈·PR·브랜치 상태를 대조한다. 응답 유실만으로 같은 게시를 반복하지 않는다.

기본 `review` 종료점은 검토된 후보를 보존하며 자동 병합하지 않는다. `land`는 초기화 시 `--endpoint land --allow-land`를 함께 지정하고 별도 권한을 확보한 경우다. 랜딩 후에도 트리아지(triage: 남은 사항을 분류·처리하는 후속 점검)가 필요하다. 원래 요구의 결함을 새 TODO나 Watch로 옮겨 완료 처리하면 안 된다.

“원자적 완료”는 완료 상태와 관련 기록을 한 묶음으로 확정해 중간 상태에서 중복 배정되지 않게 하는 뜻이다. 모든 작업이 동시에 끝나거나 검증이 필요 없어진다는 뜻은 아니다.

## 8. 관찰 사항과 후속 작업

```sh
todo-flow --state "$FLOW_STATE" watches
todo-flow --state "$FLOW_STATE" signal ACTUAL_TRIGGER --version ACTUAL_VERSION
```

관찰에는 무엇을 봤는지, 지금 미루는 이유, 어떤 변화가 재평가를 일으키는지, 그때 무엇을 할지를 남긴다. 같은 신호를 새 작업처럼 반복 등록하지 않는다. 비활성 트랙의 신호만으로 새 코드 실행이 시작되지는 않는다. 실제 수정이 필요한 후속 TODO는 등록한 뒤 사람이 다시 선택한다.

Jev는 선택적 조사 보조 도구다. TODO Flow 사용의 필수 설치 조건이 아니며 점수만으로 해결을 판정하지 않는다.
